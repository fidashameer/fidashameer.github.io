Explanation Reliability Under Model Compression
ongoingmeasured on real ANE hardware
Python · PyTorch · Core ML · Apple Neural Engine · Explainable AI course project

Do the explanations produced by a quantized model still describe the model that actually runs on the device? I measured this on Apple Neural Engine hardware, and the answer turns out to depend heavily on something nobody usually checks: how many images were used to calibrate the quantization.

Attribution reliability vs. calibration set size (on-device)
Full-precision reliability stays flat throughout (spread 0.0045 / 0.0075) — the control, since it never sees calibration data.

The collapse is overwhelmingly on the deployed model, not the simulated path most research uses. Simulated-path reliability stays essentially flat on both architectures (0.884 / 0.891 / 0.891 on ResNet18 and 0.690 / 0.696 / 0.712 on ResNet50). It is not exclusive to the deployed path, though — simulated-path agreement with full precision does rise on ResNet50, from an attenuation-corrected 0.860 to 0.926. The effect is roughly an order of magnitude larger on device, which is the honest way to state it.

The practically important part: accuracy does not warn you. ResNet50 quantized with 20 calibration images agreed with full precision on 93% of predictions while its attribution reliability sat at 0.318 against full precision's 0.709. Standard accuracy-based deployment validation passes that model — and its explanations are barely reproducible. On ResNet18 accuracy degrades alongside reliability, so routine testing would catch it. The dissociation is architecture-specific and can't be assumed either way without measuring.

The measurement was harder than the experiment. Single-grid occlusion attribution self-correlates at only 0.309 on ResNet50 — the map barely agrees with itself when the grid shifts eight pixels. That figure is architecture-specific: ResNet18 sits at 0.609, and ResNet50 is the weaker instrument throughout (full-precision reliability 0.705 against ResNet18's 0.894), so its numbers carry more noise. Averaging over four grid offsets raises ResNet50 to 0.737. Every conclusion I drew before finding that was an artefact of one arbitrary grid placement.

I applied correction for attenuation — the correlation between two noisy measurements is bounded by √(r₁×r₂), not 1 — to separate "these models attend to different regions" from "one of them is noisy," validated against synthetic data with known ground truth. On-device execution was verified by querying Apple's MLComputePlan (120/120, 282/282, 408/408 operations on the ANE) rather than inferred from a 4.7× speedup. RISE was implemented, tested and rejected (0.48–0.53, worse than occlusion).

Three preliminary findings were reversed by their own controls, and all three remain in the commit history. A protocol that has never rejected anything provides no evidence that it could.

Limits: two architectures, both ResNets. One dataset, one hardware platform, one attribution method. Gradient-based attribution was impossible — Core ML exposes no gradients, so Grad-CAM and Integrated Gradients could not run on the deployed model, which is the largest gap between this and the paper that motivated it. Reliability is not correctness.

Behavioral Anomaly Detection + MITRE ATT&CK Attribution
ET AI Hackathon 2026 · solo build
Python · scikit-learn · Streamlit · Claude API

Signature-based detection misses APTs that deliberately operate low-and-slow. This builds the behavioral alternative: a per-entity baseline from flow-aggregated network data, scoring each time window by how far it deviates from that entity's own history — ensembling Isolation Forest (jointly-unusual feature combinations), a statistical max-deviation scorer (single-feature spikes), and a peer-novelty signal (entities reaching hosts they've never contacted).

Synthetic set: 7,200 five-minute windows across 60 entities at a 5.7% attack base rate. Real UNSW-NB15: 2.54M connections across 43 hosts, aggregated to the same per-entity schema and run through the engine unmodified. The gap is a genuine finding, not something to explain away — UNSW's dominant categories are Exploits and Fuzzers, which don't produce the sustained shifts in aggregate flow statistics that a behavioral-baseline method is built to catch. That's a limitation of the method, not just the dataset.

A feature-engineering trade-off worth showing rather than hiding. An attacker moving laterally with stolen-but-valid credentials over SMB/RDP doesn't shift enough volume to look anomalous — measured deviations were under 1 SD from baseline. But reaching hosts an entity has never contacted is a sparser signal independent of volume. Adding novel_peer_ratio (tracked causally, using only windows strictly before the current one, so no label leakage):

The engine flags a fixed number of windows per run. Once peer-novelty made lateral-movement windows rank higher, borderline brute-force windows that previously just cleared the cutoff no longer did — at the same total alert volume. Net effect was positive across every headline metric, but it's a real illustration that improving one axis can cost another sharing the same alert budget.

Paired with an attribution agent retrieving MITRE ATT&CK techniques matching each alert's triggering features: 96.2% top-1 and 98.8% top-3 technique-level accuracy, measured against simulator ground truth rather than asserted.

Stated openly: the primary dataset is synthetic (the build sandbox couldn't reach Kaggle/UCI/HuggingFace); the ATT&CK knowledge base is a hand-curated 18-technique snapshot, not a live TAXII feed; and three of the problem statement's five sub-agents were deliberately not built rather than half-built and demoed with false confidence.

Predictive vs. Reactive SDN Load Balancing Under Flash-Crowd Traffic
negative resultIEEE-format paper
Python · Ryu · Mininet · OpenFlow · Open vSwitch

Application-layer service meshes (Envoy, Linkerd) use EWMA-smoothed latency scores to bias traffic toward faster backends, and it works well there. Does the same technique still help once you move it down a layer, into an SDN controller that only sees OpenFlow port statistics instead of real response latencies?

Four controllers implemented in Ryu over a Mininet/Open vSwitch testbed, with P95/P99 tail latency measured across seven or more independent runs per configuration, over homogeneous and heterogeneous (1:2:4) server pools, under burst and steady traffic.

P99 tail latency, ms — mean, with ± SD whiskers
Stable (SD < 5ms) Unstable (SD > 15ms) Whiskers = ±1 SD across runs

Round-robin and weighted round-robin are both the fastest and the most stable. EWMA's standard deviation runs 14–28× larger — not just "no better on average," but markedly less predictable run to run.

α-sensitivity sweep — heterogeneous, burst (hover a point)

Moderate smoothing (α 0.1–0.7) sits in a comparable band; at α = 0.9 the balancer thrashes and P99 collapses to ~240ms.

The answer was no: EWMA never beats plain round-robin, in any tested condition. The mechanism is clear once you see it — smoothing is designed to reject transient noise, but a persistently slow server isn't noise, it's a stable signal that needs an immediate reaction. The property that would help during a bursty homogeneous flash crowd is exactly the one that hurts under sustained heterogeneity. Reported as a negative result with a mechanistic explanation rather than dressed up as a win.

Causally-Consistent Counterfactual Recourse
Python · scikit-learn · DiCE · Gradio · Explainable AI course project

Counterfactual explanation tools tell someone what would need to change for a model's prediction to flip — but they vary features independently, and can recommend combinations that aren't jointly realistic (increase insulin resistance while blood glucose drops, which doesn't happen physiologically). I measured how often that occurs and compared three fixes, using a random forest on the Pima Indians Diabetes dataset across 25 test-set patients predicted high-risk.

MethodCoverageCausal consistencyMean distance
Baseline DiCE100%86%4.23
Filtered DiCE100%*100%3.94
Structural (ours)60%100%1.14

* Sample-dependent, not guaranteed. The structural method's consistency is mathematically guaranteed by construction, not merely observed.

14% of baseline DiCE's counterfactuals are causally inconsistent, most often by suggesting Insulin and Glucose move in opposite directions when the literature-grounded relationship says they move together. The structural method — varying only the actual root cause (BMI) and deriving the rest — guarantees consistency but fails to find a recommendation for 40% of patients, because it has one lever to work with. Neither method is a strict win, and the report treats it as a real trade-off rather than a solved problem.

Limits: the causal graph is a literature-grounded simplification, not a validated causal model; structural equations are simple linear regressions with low explained variance; 768-row dataset. Demonstrates the method, not clinical validity.
